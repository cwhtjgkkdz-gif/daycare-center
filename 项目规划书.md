# 托育中心管理系统 - 项目规划书

## 一、项目概述

### 1.1 项目背景

随着"三孩政策"全面实施，0-3岁婴幼儿托育需求激增。然而大量托育机构仍依赖纸质档案+Excel管理，存在数据分散、查询低效、财务混乱、信息孤岛等问题。本系统旨在为托育中心提供一套完整的信息化管理平台。

### 2.2 Session 认证 vs JWT vs Spring Security

| 方案 | 优点 | 缺点 | 本项目选择理由 |
|------|------|------|-------------|
| **Session(本项目)** | Servlet原生支持，无需Token表，服务端可控过期 | 分布式需共享Session | 单体部署足够，简单可靠 |
| JWT | 无状态，适合微服务 | 无法主动失效，Token泄露风险 | 过度设计 |
| Spring Security | 功能全面 | 配置复杂，学习曲线陡 | 本项目只需基础认证 |

### 2.3 LoginInterceptor 拦截器详解

```java
@Component
public class LoginInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
        // === 白名单放行 ===
        String uri = req.getRequestURI();
        if (uri.contains("/doc.html")       // Knife4j文档页
            || uri.contains("/v3/api-docs") // OpenAPI规范JSON
            || uri.contains("/webjars"))    // Swagger UI静态资源
            return true;

        // === Session校验 ===
        HttpSession session = req.getSession(false); // false:不创建新Session
        if (session != null && session.getAttribute("loginUser") != null)
            return true;

        // === 未登录返回401 ===
        res.setStatus(401);
        res.setContentType("application/json;charset=UTF-8");
        res.getWriter().write("{\"code\":401,\"message\":\"未登录，请先登录\"}");
        return false;
    }
}
```

注册在 WebConfig：
```java
registry.addInterceptor(loginInterceptor)
    .addPathPatterns("/api/**")              // 拦截所有API
    .excludePathPatterns("/api/auth/login"); // 登录接口放行
```

### 2.4 前端401处理

```javascript
// api/request.js — Axios响应拦截器
request.interceptors.response.use(
  res => {
    if (res.data.code !== 200) {
      ElMessage.error(res.data.message || '请求失败')
      return Promise.reject(new Error(res.data.message))
    }
    return res.data
  },
  err => {
    if (err.response?.status === 401) {
      ElMessage.error('请先登录')
      window.location.href = '/login'  // 硬跳转，清空所有状态
    } else {
      ElMessage.error(err.message || '网络错误')
    }
    return Promise.reject(err)
  }
)
```

### 2.5 刷新页面Session恢复

```
用户按F5刷新 → Vue重新初始化 → Pinia Store重置为null
→ router.beforeEach检查到!store.isLoggedIn
→ 调用 GET /api/auth/info → 后端从Session取出user → 重新查库获取最新数据
→ store.setUser()恢复状态 → 放行（用户无感知）
```

### 3.2 三种角色的菜单分配

| 角色 | role_code | 拥有的菜单 | 说明 |
|------|-----------|-----------|------|
| 超级管理员 | ROLE_ADMIN | **全部12个** (首页+系统管理/用户管理/角色管理/菜单管理/班级/儿童/教职工/活动/通知/财务/考勤) | 系统最高权限 |

### 3.3 权限生效流程

```
1. DataInitializer启动时插入3角色+12菜单+关联数据
2. 管理员可在「角色管理→分配权限」界面修改任意角色的菜单
3. 用户登录 → getUserMenus(roleId)
   → 查sys_role_menu获取该角色的menu_id列表
   → 查sys_menu获取菜单详情(只要visible=1的M和C类型)
   → 递归buildTree()
4. 前端Sidebar.vue根据menus数组动态渲染
5. 后端LoginInterceptor仅校验登录态（未做接口级权限）
   前端控制: 不同角色看到不同菜单 → 无法点击未授权的页面
```

### 3.4 角色分配权限的实现

```java
// RoleServiceImpl.assignMenus() — 分配权限核心逻辑
public boolean assignMenus(Long roleId, List<Long> menuIds) {
    // 第一步：删除该角色所有旧的菜单关联
    roleMenuMapper.delete(
        new LambdaQueryWrapper<RoleMenu>().eq(RoleMenu::getRoleId, roleId));
    // 第二步：逐个插入新的关联
    for (Long menuId : menuIds) {
        RoleMenu rm = new RoleMenu();
        rm.setRoleId(roleId);
        rm.setMenuId(menuId);
        roleMenuMapper.insert(rm);
    }
    return true;
}
```

## 四、数据库完整设计

### 4.1 设计原则

1. **三范式**：消除数据冗余，每表独立实体
2. **物理外键**：6条FK约束保证引用完整性，不设CASCADE（采用逻辑删除）
3. **逻辑删除**：所有表is_deleted字段，DELETE转UPDATE，数据可恢复
4. **自动填充**：create_time/update_time通过MetaObjectHandler自动设now()
5. **统一基类**：BaseEntity包含id+createTime+updateTime+isDeleted
6. **字符集**：utf8mb4支持emoji等4字节字符
7. **引擎**：InnoDB支持事务+外键+行级锁

### 5.2 Entity 层设计

每个实体 = `@TableName`映射表 + `extends BaseEntity`继承通用字段 + `@TableField(exist=false)`标记非数据库字段。

```java
// 以 Child 为例
@Data
@EqualsAndHashCode(callSuper = true)
@TableName("child")
public class Child extends BaseEntity {
    private String name;
    private String gender;
    @JsonFormat(pattern = "yyyy-MM-dd")     // 前后端日期格式对齐
    private LocalDate birthDate;
    private Long classId;                   // 外键 → class_info.id
    private String parentName;
    private String parentPhone;
    private String allergies;
    private Integer status;                 // 1在园/0离园

    @TableField(exist = false)             // 非数据库字段
    private String className;              // Service层关联查询填充
}
```

### 5.3 Mapper 层设计

每个 Mapper = `@Mapper` + `extends BaseMapper<Entity>`，即可获得完整CRUD能力。

```java
@Mapper
public interface ChildMapper extends BaseMapper<Child> {
    // 空接口 — BaseMapper自动提供:
    // insert(T entity)                    插入一条（自动填充createTime/updateTime）
    // deleteById(Serializable id)         删除一条（@TableLogic转为逻辑删除）
    // updateById(T entity)                按ID更新（自动填充updateTime）
    // selectById(Serializable id)         按ID查询
    // selectList(Wrapper<T> wrapper)      条件查询列表
    // selectPage(Page<T> page, Wrapper)   分页查询（拦截器自动COUNT+LIMIT）
    // selectCount(Wrapper<T> wrapper)     计数
}
```

特殊 Mapper（需要自定义SQL的方法，用注解写SQL）：
```java
// RoleMenuMapper — 需要自定义查询
@Mapper
public interface RoleMenuMapper extends BaseMapper<RoleMenu> {
    @Select("SELECT menu_id FROM sys_role_menu WHERE role_id = #{roleId} AND is_deleted = 0")
    List<Long> selectMenuIdsByRoleId(@Param("roleId") Long roleId);
}
```

### 5.4 Service 层设计

以 ChildServiceImpl 为例说明标准实现模式：

| 方法 | 实现 | 关键技术点 |
|------|------|-----------|
| `page()` | 构建LambdaQueryWrapper → selectPage → fillClassName | like条件用StringUtils.hasText判断是否生效；eq条件用!=null判断；分页由PaginationInnerInterceptor自动COUNT+LIMIT |

### 5.5 Controller 层设计

统一模式：`@Tag`分组 + `@Operation`说明 + `@OperationLog`日志 + `@RequestMapping`路径 + `Result<T>`返回。

```java
@Tag(name = "儿童档案")                          // Knife4j分组名
@RestController
@RequestMapping("/api/child")                    // 统一路径前缀
public class ChildController {
    @Autowired private ChildService childService;

    @Operation(summary = "分页查询儿童")          // 接口说明
    @GetMapping("/page")
    public Result<PageResult<Child>> page(
            @RequestParam(defaultValue = "1") int current,   // 默认值
            @RequestParam(defaultValue = "10") int size,
            @RequestParam(required = false) String name,     // 可选参数
            @RequestParam(required = false) Long classId,
            @RequestParam(required = false) Integer status) {
        Page<Child> page = childService.page(current, size, name, classId, status);
        return Result.ok(PageResult.of(page.getTotal(), page.getCurrent(), page.getSize(), page.getRecords()));
    }

    @OperationLog(module = "儿童档案", operation = "新增儿童")  // 触发AOP日志
    @PostMapping
    public Result<Void> add(@RequestBody Child child) {
        childService.add(child);
        return Result.ok("新增成功");              // Result.ok(String) → Result<Void>
    }
    // ... 其他CRUD方法结构相同
}
```

## 七、AOP操作日志

### 7.1 设计思路

在 Controller 方法上加 `@OperationLog` 注解 → AOP 环绕通知自动记录 → 存入 sys_operation_log 表。业务代码与日志记录零耦合。

### 7.2 实现

```java
// 1. 注解定义
@Target(ElementType.METHOD) @Retention(RetentionPolicy.RUNTIME)
public @interface OperationLog {
    String module() default "";     // 模块名
    String operation() default "";  // 操作类型
}

// 2. 切面实现
@Aspect @Component
public class OperationLogAspect {
    @Around("@annotation(opLog)")
    public Object around(ProceedingJoinPoint jp, OperationLog opLog) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = jp.proceed();               // 执行目标方法
        long cost = System.currentTimeMillis() - start;
        try {
            OperationLogEntity log = new OperationLogEntity();
            log.setModule(opLog.module());           // 从注解取值
            log.setOperation(opLog.operation());
            log.setMethod(jp.getSignature().toShortString()); // "ChildController.add()"
            log.setCostTime(cost);
            User user = (User) session.getAttribute("loginUser");
            if (user != null) log.setOperator(user.getUsername());
            log.setIp(request.getRemoteAddr());
            operationLogMapper.insert(log);
        } catch (Exception e) { log.error("日志失败", e); }  // 不影响业务
        return result;
    }
}

// 3. 使用
@OperationLog(module = "儿童档案", operation = "新增儿童")
@PostMapping
public Result<Void> add(@RequestBody Child child) { ... }
```

### 10.2 启动步骤

```bash
# 1. 初始化数据库
mysql -u root -p
CREATE DATABASE `daycare-center` DEFAULT CHARSET utf8mb4;
USE `daycare-center`;
source src/main/resources/db/init.sql;
source src/main/resources/db/data.sql;

# 2. 修改application.yml中的数据库密码

# 3. 启动后端
cd daycare-center-backend
mvn spring-boot:run
# 看到 "Started DaycareCenterBackendApplication" 即成功
# 访问 http://localhost:8080/doc.html 验证Knife4j正常

# 4. 启动前端
cd daycare-center-frontend
npm install
npm run dev
# 访问 http://localhost:5173
# 登录 admin / admin123
```
